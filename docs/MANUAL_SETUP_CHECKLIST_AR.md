- [x] قاعدة Supabase الحية تحتوي 15 جدولاً عاماً للتطبيق، وRLS مفعّل على جميعها.
- [x] سياسات التخزين الخاصة بالكتب والمجسمات تمنع رفعها من غير الإدارة.
- [x] تمت مطابقة أرقام 44 ملف ترحيل محلياً مع 44 رقماً في سجل Supabase الحي؛ لم يُنفّذ `db push` أو `db reset` بعد.
- [x] أزيل معرّف التهيئة الشخصي من محتوى ملف الترحيل الحالي؛ يبقى موجوداً في تاريخ Git القديم ويحتاج موافقة صريحة قبل إعادة كتابة التاريخ.
- [x] وظائف إنشاء الحساب وتغيير الدور تتحقق من JWT وصلاحية المالك على الخادم.
- [x] تضييق قراءة طلبات الإجازة وتقارير المراقبين إلى الشعبة نفسها.
- [x] منع المرشد التربوي من وراثة صلاحيات المدير العامة؛ صلاحياته الإرشادية الخاصة ما زالت تحتاج تصميماً مستقلاً.
- [x] تقييد إسناد القرارات بحساب مراقب شعبة فقط.
- [x] مفاتيح service_role غير موجودة في تطبيق Android، وصلاحياتها على الجداول العامة مقيدة.
- [x] تغييرات تشفير refresh token، تقييد FileProvider، والتحقق من مصدر/حجم التحديث محفوظة على الفرع؛ يلزم نجاح CI الأحدث لاعتمادها.

## المطلوب قبل إطلاق المدرسة

1. [ ] **انتظار نجاح أحدث CI:** افتح [GitHub Actions](https://github.com/mostafa0782/RUVEN/actions) وتحقق أن أحدث تشغيل على `feature/ruven-announcements` نجح على نفس commit الحالي. هذا الفرع ينتج APK تجريبياً غير موقّع بمفتاح الإصدار؛ لا تستخدمه كتحديث فوق النسخة الرسمية.
2. [ ] **تهيئة Supabase CLI وإعادة تشغيل المخطط محلياً:** نفّذ `supabase init` لأن `supabase/config.toml` غير موجود، ثم `supabase link --project-ref ijvfjvfmpvydbclgzyac`، وتأكد من `supabase migration list`، ثم اختبر `supabase db reset` محلياً. لا تنفذ `db push` إذا ظهر أي اختلاف أو فشل. التفاصيل في `supabase/README.md`.
3. [ ] **تفعيل حماية كلمات المرور المسرّبة:** من إعدادات Supabase Auth، فعّل Leaked Password Protection إذا كانت متاحة لخطة المشروع، ثم أعد فحص Security Advisor. هذا الإعداد لا يتم عبر SQL.
4. [ ] **اختبارات RLS متعددة الحسابات:** أنشئ حسابين تجريبيين لمراقبي شعبتين مختلفتين، وتحقق أن كل واحد لا يستطيع قراءة إجازات أو تقارير الشعبة الأخرى، وأن الطالب العادي لا يستطيع قراءة قرار مخصص لمراقب. اختبر أيضاً أن المرشد التربوي لا يرى لوحات الإدارة العامة.
5. [ ] **اختبار عملي على جهاز Android:** اختبر تسجيل الدخول، ترحيل الجلسة القديمة إلى التخزين المشفر، استعادة الجلسة، تسجيل الخروج، الإشعارات، رفع/قراءة المرفقات، وفتح ملف التحديث وتثبيته.
6. [ ] **حماية بيئة التوقيع:** أنشئ GitHub Environment باسم `release-signing`، واجعل النشر مسموحاً من `main` فقط، وفعّل موافقة مراجع موثوق قبل تشغيل أي job يستخدم مفتاح التوقيع.
7. [ ] **تثبيت مفتاح التوقيع:** تأكد من إعداد أسرار GitHub الأربعة: `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. لا تشارك قيمها ولا تغيّر المفتاح بعد توزيع النسخة.
8. [ ] **اعتماد سياسة الخصوصية:** تحتاج موافقة المدرسة، وبيانات اتصال رسمية، ومدد احتفاظ وحذف، وإشعاراً مناسباً لأولياء أمور الطلبة القاصرين.
9. [ ] **تأكيد هوية المدرسة قبل تعدد المدارس:** لا تضف مدرسة ثانية إلى مشروع Supabase الحالي قبل اعتماد المدرسة الحالية وربط كل السجلات بعضويات مدرسية واختبار العزل بين مدرستين.
10. [ ] **اختبار النسخة الرسمية:** إصدار 0.1.x يجب أن يكون رقم patch فيه أعلى من رقم أحدث تشغيل Android CI على commit نفسه؛ سيرفض workflow الإصدار إذا كان `versionCode` غير قابل للتحديث.

## تنبيهات

- الفرع الحالي هو `feature/ruven-announcements`، وPull Request رقم 1 ما زال غير مدمج.
- لا تعتبر التطبيق جاهزاً للإطلاق لمجرد نجاح البناء؛ يلزم اختبار فعلي للأدوار والجلسات والتحديثات.
- لا تضع مفتاح service_role أو بيانات طلاب حقيقية في GitHub أو ملفات Android.
- سياسة الخصوصية والشروط الحالية مسودات وليستا اعتماداً قانونياً أو وزارياً.
- لا تُعد كتابة تاريخ Git لإزالة معرّف قديم دون مراجعة أثرها وموافقة صريحة؛ إزالة الملف الحالي لا تمحو النسخ السابقة من تاريخ Git.
